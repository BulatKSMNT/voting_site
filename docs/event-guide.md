# Туры, раунды и проведение мероприятия

Кампания — одно мероприятие. В ней есть туры. В индивидуальном туре каждому
выступающему соответствует отдельный раунд «ДА/НЕТ», который администратор
выбирает по фамилии и имени. Общий тур содержит одно голосование за весь состав.
Приватный доступ задаётся для кампании и действует во всех её турах и раундах.

## Создание и проведение через бота

1. Создайте кампанию командой `/create_campaign`, при необходимости настройте
   список допущенных зрителей через `/campaign_access`.
2. Откройте `/event` → мероприятие → **«Создать тур» → «Индивидуальный (ДА/НЕТ)»**.
   Укажите число лучших **различных значений баллов N** (для вашего мероприятия — 8).
3. В карточке тура нажмите **«Добавить участника / список»**. Можно прислать одно
   имя или список, каждое имя с новой строки. Не нужно заранее собирать 25 имён:
   участников можно добавлять до завершения тура. Каждому создаётся свой раунд.
4. Выберите **«Раунд: Фамилия Имя» → «Открыть голосование ДА/НЕТ»**. Порядок
   выступлений выбирает администратор. Зрители голосуют через `/vote`.
5. После выступления нажмите **«Завершить этот раунд»**, вернитесь к туру и
   откройте раунд следующего участника. Закрытие раунда сохраняет результат в
   общей таблице тура и само по себе не переводит выступающего в следующий тур.
6. Когда все выступления завершены, в карточке тура нажмите
   **«Завершить ТУР и перенести топ-N»**. Проходящие автоматически попадают в
   следующий общий тур, с нулём голосов. Повторное нажатие не создаёт дубликаты.

Одновременно в кампании открывается одно голосование. Незавершённое выступление
не даёт закрыть весь тур. Число N меняется через кнопку **«Настроить уровни баллов: топ-N»** до завершения тура, в том числе когда выступления уже идут.
Можно также воспользоваться `/set_winners_count`.

Для массовой первоначальной загрузки в пустой кампании есть отдельная кнопка
**«Загрузить сразу список выступающих»**: по умолчанию отбирается топ-8, затем N
можно изменить. Список содержит от 1 до 100 участников. Совпадающие имена нужно
уточнить, чтобы ведущий мог однозначно выбрать нужный раунд.

## Общее голосование и финал

В общем туре каждый Telegram ID может поддержать **не более трёх разных людей**.
Повторный голос за того же участника не принимается. Все участники отображаются
на сайте; лимит топ-N для публичной таблицы применяется только к индивидуальному
туру. Ответы «нет» сохраняются в истории и не вычитаются из числа «да» при отборе.

После первого тура общий тур создаётся с отбором двух лучших уровней баллов по умолчанию.
Главный администратор может изменить N до завершения. Завершение общего тура
создаёт финал с топ-N и обнуляет голоса. Финал ждёт отдельного открытия.

До запуска финала главный администратор может добавить **одного** участника
независимо от голосов: выбрать из общего тура либо ввести фамилию и имя нового
финалиста. Эти действия занимают одно дополнительное место; новый выбор заменяет
старый. Топ-N сохраняется. Если выбранный заранее участник прошёл по голосам,
дубликат не создаётся; можно выбрать другого дополнительного участника.

В финале каждый зритель выбирает только одного финалиста. Победитель один.
После открытия финала состав не меняется. Сервер проверяет лимиты, права и доступ
также для старых кнопок и одновременных запросов.

Общий тур можно создать и первым, кнопкой **«Создать тур» → «Общий»**.
Участников такого тура добавляют до открытия голосования.

## Топ-N по баллам и равенство

N — число лучших различных значений баллов, а не ограничение числа людей.
При N=2 и баллах **10, 10, 8, 8, 5** проходят первые четверо: уровни 10 и 8.
В таблице их места — **1, 1, 2, 2**. Правило одинаково используется для публичного
топа индивидуального тура, результатов бота и переноса в следующий тур.
В общем голосовании сайт по-прежнему показывает весь состав, отмечая проходящих.

На проходном уровне сохраняются все участники с одинаковым результатом;
выбирать между ними вручную не нужно. Если различных значений меньше N, проходят
все. Ноль тоже является значением баллов: при нулевых результатах все участники
делят первое место. Дополнительное место главного администратора добавляется
сверх отобранных по баллам, без дублирования уже прошедшего участника.

В финале остаётся один победитель. Если несколько финалистов набрали одинаковый
максимальный результат, голосование закрывается и главный администратор выбирает
одного из них через **«Разрешить равенство голосов»**.

Завершённые до изменения правила туры сохраняют прежний зафиксированный отбор;
уже выполненные переходы и исторические снимки результатов не пересчитываются.
Незавершённый тур, который ожидал выбора при равенстве, можно завершить заново:
теперь все участники с проходными баллами перейдут автоматически.

## Админка и прежние команды

В **Campaigns → «Подготовить / открыть туры»** доступны создание тура и вложенные
раунды с ФИО. В карточке тура можно добавить участников и изменить N. В карточке
конкретного раунда — открыть и завершить его. Там же остаются результаты,
история, дополнительный финалист и выбор при равенстве.

Раунды, созданные прежними командами, отображаются в `/event`. Их участники,
голоса и история сохраняются без преобразования. Для них сохранён прежний
ручной процесс `/start_round`, `/add_participant`, `/set_current_round`,
`/end_current_round`: перенос в выбранный общий раунд с выбором сохранения голосов.
Для подготовленных туров команды выбора/добавления открывают соответствующие
карточки или используют ту же проверяемую операцию добавления.

Модератор может выбирать, запускать и завершать голосования. Создание туров,
добавление участников, настройка N, дополнительный победитель и разрешение ничьих
доступны главным администраторам. После изменения `FULL_ADMIN_IDS` в `.env`
пересоздайте оба контейнера: `docker compose up -d --no-build web bot`.

## Табло на весь экран

На странице результатов нажмите **«На весь экран»**. Шапка, подвал и навигация
между турами скрываются; остаётся табло голосования. Режим сохраняется при
автоматической смене тура. Выход — Escape или кнопка в правом нижнем углу,
появляющаяся при наведении. При полноэкранном режиме самого браузера (F11)
шапка и подвал также скрываются; выход из него — F11.

## Проверки и обновление

`python manage.py test voting tg_bot --settings=core.test_postgres_settings`
запускает проверки на отдельной PostgreSQL: 25 выступлений → 8 → 2 + дополнительный
финалист → победитель, произвольный топ-N, добавление по одному, старые раунды,
приватный доступ, ничьи, роли, лимиты 3/1 и конкурентные запросы. Telegram-тесты
исполняют обработчики, подменяя отправку сообщений.

Обновление меню не требует новой миграции после `0008`. Обновляйте web и bot
совместно, сохраняя резервную копию БД по [инструкции эксплуатации](operations.md).

Кнопка **«Создать тур»** доступна главному администратору внутри выбранного
мероприятия, даже если другой тур ещё не завершён. Путь: `/event` → мероприятие →
**«Создать тур»** → тип: общий или индивидуальный.
Можно подготовить следующий тур заранее. При переходе используется первый
более поздний пустой тур подходящего типа; если такого нет, он создаётся
автоматически. Тур с уже добавленными участниками не перезаписывается.
